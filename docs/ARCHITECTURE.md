# NAVI Core architecture

NAVI is a provider-independent engineering framework. The selected external host uses advisory instructions and local commands; no model SDK is required by Core.

## Boundaries
- CLI: argument handling, manifest validation and fixed verification profiles.
- NEF: reference profiles, documentation mapping, additive scaffold and migration, structured task brief, reviewed local lessons.
- Agent Bridge: deterministic per-host instruction rendering and conflict-safe creation.
- Skill registry: quarantine, explicit license/review selection and bounded context.
- Verification and evidence: trusted project gates, scoped proofs and synthetic benchmark.
- Governance: operation reservation and policy preflight; not a global sandbox.
- Providers: optional synthetic loopback experiment; no automatic switching or required Nexus.

## Data flow
User and selected host define the task. NEF validates the submitted brief; the host consults references and a roadmap, acts within permission boundaries, verifies with existing project gates and records handoff. Explicitly reviewed lessons may be stored outside Git and selected into later context.

## Constraints
No fixed project directory layout. Do not expose private logs, credentials or lessons. CI remains deterministic without AI credentials. Host instruction adherence and semantic architecture checks require separate validation.

- UAI: portable public context, structured handoff and optional read-only MCP reference tools. No host installation or private context exposure.
